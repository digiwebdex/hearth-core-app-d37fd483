# 09 — UI / UX Standards

> 🧊 **ARCHITECTURE FREEZE (v2) — 2026-07-05.** Authoritative frozen design: [11-Architecture-Freeze](11-Architecture-Freeze.md).
> - Sidebar, feature visibility, and gating are driven by the **Module Registry** (single source). UI never hard-codes navigation or entitlements ([11 §Final Module Registry](11-Architecture-Freeze.md)).

> Frontend conventions for the ERP app, tenant public sites, and portal. Grounded in the existing `src/` stack; where a point is aspirational (not yet enforced) it's marked **[standard]** vs **[enforced]**.

## 1. Stack & building blocks

| Concern | Choice | Notes |
|--------|--------|------|
| Framework | React 18 + TypeScript + Vite | `@/` alias → `src/` (`vite.config.ts` + tsconfig) |
| UI kit | **shadcn/ui** on **Radix** primitives | components in `src/components/ui/` — compose these, don't hand-roll dialogs/selects/tabs |
| Styling | **Tailwind** (+ `tailwindcss-animate`, `@tailwindcss/typography`) | use tokens/utilities; avoid inline styles |
| Icons | **lucide-react** | one icon set — don't mix icon libraries |
| Data | **TanStack Query** | server state via `queryClient`; no ad-hoc fetch-in-effect |
| Forms | **react-hook-form + zod** (`@hookform/resolvers`) | schema-validated forms |
| Toasts | **sonner** + shadcn `toaster` | use `use-toast` hook / `Sonner` |
| Charts | **recharts** | see the `dataviz` skill before building charts |
| i18n | **i18next** (`react-i18next`) | EN + BN; browser language detector |
| Routing | **react-router-dom v6** | all routes in `src/App.tsx` |

## 2. Bilingual (EN/BN) is a first-class requirement

- **[enforced]** Navigation uses i18n keys (`titleKey`, e.g. `sidebar.dashboard`), never hard-coded labels.
- **[standard]** All user-facing strings — page copy, buttons, **empty states, error messages, toasts** — go through i18n with EN + BN. Bangla-first is a product principle ([01-Vision](01-Vision.md)).
- Service types and catalog items ship bilingual labels (`getLocalizedServiceTypeLabel`); reuse those helpers rather than re-translating.
- Use `LanguageSwitcher`; respect the detected language.

## 3. Standard state components — always use them

The app has canonical components for the four screen states. **Use them instead of bespoke markup** so every page feels the same:

| State | Component |
|-------|-----------|
| Loading | `LoadingState` / shadcn `Skeleton` |
| Empty | `EmptyState` |
| Error | `ErrorState`, wrapped by `ErrorBoundary` |
| Errors → human copy | `useHumanError` / `humanErrors.ts` (map API errors to friendly BN/EN messages) |

Lazy routes render a `Skeleton` fallback (see `Suspense` usage in `App.tsx`) — match that pattern for new lazy pages.

## 4. Gating in the UI (must mirror the backend)

UI visibility is **cosmetic** — the backend still enforces everything ([07](07-Permission-Matrix.md), [08](08-Plan-Feature-Matrix.md)). But the UI must **not** show actions a user can't perform. Use the existing gates:

| Gate | Purpose |
|------|---------|
| `ProtectedRoute` (`P`) | requires auth |
| `PermissionRoute` (`PM`) / `PermissionGate` | RBAC module+action ([07](07-Permission-Matrix.md)) |
| `AdminRoute` (`A`) | super-admin only |
| `FeatureGate` / `usePlanAccess` | plan feature flags ([08](08-Plan-Feature-Matrix.md)) |
| `SubscriptionGate` / `SubscriptionRoute` | active-subscription wall (402 → `/subscription`) |
| `HajjModuleGate` / `BdModuleGate` / `requiredServiceTypes` | service-type-driven module visibility ([04](04-Service-Modules.md)) |
| `usePermissions().hasPermission(module, action)` | conditional buttons/menu items |

**Rule:** if a route/button is backend-guarded, wrap it in the matching gate. Never rely on hiding alone; never show a control the API will 403.

## 5. Navigation & information architecture

- Sidebar is generated by `getNavigationGroups()` — **add items there**, with the correct `module`, `minPlan`, `requiredFeature`, `requiredServiceTypes`. Don't hard-code nav.
- 10 groups (Overview, CRM, Sales & Bookings, Tour & Group Travel, Operations, Finance & Accounts, HR & Payroll, Marketing & Loyalty, Website & CMS, Administration) — place new features in the right group ([04](04-Service-Modules.md)).
- **One flow, one place:** prefer single-page-with-tabs over scattering a workflow across routes (e.g. Bookings, Catalog). Provide **Next-Step** affordances (`WorkflowNextStep`, `OnboardingChecklist`) to guide the 6-step flow.

## 6. Interaction & content standards

- **[standard]** Empty states are teaching moments — explain the feature + a primary CTA (BN-first), not just "No data".
- **[standard]** Every destructive action uses shadcn `AlertDialog` confirmation.
- **[standard]** Money: display with currency (BDT ৳) and `toLocaleString()`; use `getLimitLabel` for plan limits (`-1`→"Unlimited", `0`→"None").
- **[standard]** Dates via `date-fns`; show relative "due/overdue" cues on finance screens.
- **[standard]** Forms validate with zod and surface inline errors; disable submit while pending.
- **HMR overlay is off** (`vite.config.ts`) — watch the terminal for build errors.

## 7. Three surfaces, three shells

- **ERP app** — `DashboardLayout` / `AppSidebar*` / `TopNavbar`. Authenticated, permission-gated.
- **Public tenant website** — `PublicLayout` / `MarketingLayout`, wrapped in `WebsiteProvider` (tenant theme). Branded per tenant; SEO matters.
- **Portal** — `src/portal/` shell. Read-only, minimal, magic-link auth.

Keep these shells distinct; don't leak ERP chrome into public/portal surfaces.
